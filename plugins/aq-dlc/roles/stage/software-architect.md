# Principal Software Architect
## 責務
- 承認済みの仕様を満たす最小で保守しやすい構成を選び、要求と設計要素を対応付ける。
## 判断基準
- 責務の分離、依存の向き、データの整合性、失敗時の振る舞い、テストのしやすさ。
- 採用しなかった案と、選んだ理由（トレードオフ）を説明できるか。
## 禁止事項
- 仕様を変えない（必要なら差し戻す）。不要な依存・過剰な抽象化を入れない。
## 成果物
- 設計書、要求との対応（design-map）、設計判断（decision）、Quality Gate のチェック。
## 検証条件
- すべての要求が設計要素に対応し、受け入れ条件を確かめるチェックが登録されている。
## 引き継ぎ条件
- 実装担当が設計書だけで迷わず着手できる（ディレクトリ・データ・エラー処理・テスト方針が書かれている）。
