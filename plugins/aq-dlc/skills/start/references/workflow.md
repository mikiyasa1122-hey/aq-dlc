# 工程と、エンジンが確認する条件

フェーズは状態から自動で決まる（`next` で確認）。各工程の成果物は、作成時点の指紋と一緒に記録され、指紋が今の状態と一致するものだけが証拠になる。

```
依頼 ─▶ 要求分析 ─▶ 人間の確認 ─▶ 設計 ─▶ 実装 ─▶ Quality Gate ─▶ 独立レビュー ─▶ Memory ─▶ CI・PR ─▶（マージ後の確認）
          ▲  質問・回答 ┘            ▲        ▲          │ 不合格           │ 要修正
          └──────── 仕様の指摘 ───────┴─ 設計の指摘 ┴──── 実装・テストの指摘 ◀┘
```

## サブエージェントの起動条件（PreToolUse: Agent）

| 担当 | 起動できる条件 |
|---|---|
| 要求分析 | run が進行中で、他のサブエージェントが実行中でない |
| 設計 | 上に加えて、仕様が登録・提示・承認済みで、未回答の質問がない |
| 実装 | 上に加えて、承認済み仕様に基づく設計が登録済みで、全要求が対応付き、チェックが登録済み、未対応の差し戻しがない |
| 独立レビュー | 上に加えて、最新の実装が登録済みで、最新のコード・検証条件に対する gate が合格 |

起動は前景（run_in_background: false）に固定される。同時に2つは起動できない。

## サブエージェントの終了条件（SubagentStop）

| 担当 | 終了時に確認すること | 登録されるもの |
|---|---|---|
| 要求分析 | spec.md の必須見出し、本文に要求・受け入れ条件の ID、ID の重複なし、全要求に受け入れ条件、全受け入れ条件とリスクに検証、重要な要求に検証付きのリスク | 仕様の版（指紋） |
| 設計 | design.md の必須見出し、基にした仕様の指紋、全要求の design-map、チェックの登録 | 設計の版（指紋）、差し戻し |
| 実装 | impl.md が今回書かれたこと、設計書・仕様の指紋が最新、修正依頼の各ラベルへの対応、全要求の impl-map（ファイルが存在）、全検証の実行方法 | 実装の回（コードの指紋）、差し戻し |
| 独立レビュー | 判定が「合格」か「要修正」、重大な指摘の数と [重大n] の数の一致、「合格」と重大の矛盾なし、「要修正」なら指摘あり、全受け入れ条件と重要なリスクの妥当性評価、E2E の要否、エンジンが検出したテストの兆候への言及 | レビューの回（判定・合否・指摘・各指紋）。レビュー中にコードが変わったら無効 |

不足があると、サブエージェントは終了できずに理由を受け取る（既定3回まで。超えたら登録せずに終了し、`next` が再実行を示す）。

## 完了の条件（complete / Stop hook）

1. ID の重複がない
2. 仕様が登録済み・承認済みで、承認後に変わっていない。未回答の質問・未反映の回答がない
3. 未対応の差し戻しがない
4. 設計が最新の承認済み仕様に基づき、登録後に変わっていない。全要求が対応付き。チェックが1つ以上
5. 実装が最新の設計・仕様に基づく。全要求に実装ファイルがあり、全検証に実行方法がある
5b. 今のコードが、最後に実装担当が登録したコードと一致する（実装担当以外の操作による変更がない）
6. gate が、今のコード・チェックの定義・各検証の条件で実行され、合格し、実行中に変更がなかった
7. **最新の**レビューが有効で「合格」かつ重大0件（要修正・矛盾・判定なしは不可。最新が無効なら、前の合格も使わない）。その後にコード・検証条件・チェック・仕様・設計が変わっていない
8. 人の確認が必要な検証が、人間の返答の後に confirm されている
9. Memory 整理が済んでいる（保存・統合した Memory にこの run の証拠がある、または見送りの理由がある。読み込んだ Memory の利用結果が記録されている）
10. GitHub Actions がある場合、最新コミットの CI が成功している
11. （マージ後）`--after-merge` の検証が gate --after-merge で合格、または人間の確認済み

## 人間の確認の記録

`spec --approve`・`answer`・`confirm` は、それぞれ「提示」「質問の登録」「ask」の**後に**人間の返答（ユーザーの発言、AskUserQuestion の回答）が hook で記録されていないと受け付けない。
