# 仕様の確認で見る観点

「答えによって作るものが変わるか」で質問を選ぶ。全部を聞く必要はない。依頼文から明らかなもの、内部実装の話は聞かない。

| 観点 | 聞く例 |
|---|---|
| 利用者と利用場面 | 自分だけで使うか、他の人にも使わせるか。スマホ中心かPC中心か |
| 必須機能と優先度 | 最初の版に必ず入れるもの、後回しでよいもの |
| 今回作らないもの | ログイン、共有、通知、多言語など、入れないと決めるもの |
| 主要な操作の流れ | 最初の画面で何ができるか、1件の追加・編集・削除の流れ |
| データ | 保存場所（端末内／クラウド）、消えてよいか、バックアップ・書き出し、複数端末・複数タブ |
| 失敗時の扱い | 保存に失敗したとき、入力が不正なとき、通信が切れたときにどう見せるか |
| 境界 | 件数・文字数の上限、日付や時刻の扱い（タイムゾーン、うるう年） |
| 権限と公開 | 誰が見られるか、公開URLにするか、GitHub の公開範囲 |
| 対応環境 | ブラウザ、OS、オフライン対応の要否 |
| 完成条件 | 何ができたら完了とするか、デプロイまで含むか |

## 質問の作り方
- 1回に最大4問。選択肢は2〜4個、推奨を先頭に「（推奨）」と付ける。
- 選択肢には、選んだときに何が変わるかを短く添える。
- 聞かなかった点は推奨案で `assume` に登録し、仕様シートに載せる（後から読んで分かるように）。
